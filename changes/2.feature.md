A new barycentring engine computes the correction directly from astropy, ERFA and a
JPL ephemeris, with no PINT in the loop. It agrees with HEASOFT `barycorr` to within
the resolution the reference files can express (about 20 ns), it gives the same answer
on Apple Silicon as on x86, and it is some 30 times faster. It is not yet the default.

It is now the default. `--engine pint` keeps the old path available as an independent
cross-check, and for a `.par` file whose proper motion matters. Old ephemerides also work
again: `--ephem DE200` (or DE405, or a NANOGrav DE436) used to fail with an HTTP 404,
because astropy looks for every kernel in the one NAIF directory that no longer holds
them.
