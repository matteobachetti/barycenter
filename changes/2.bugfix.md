`--clockfile none` now actually skips the clock correction instead of failing with
`FileNotFoundError`, and a clock file is no longer applied to a mission it was not
made for.

With a `.par` file, the `PLEPHEM` header keyword now records the ephemeris the correction
was actually computed with -- the par file's -- rather than whatever `--ephem` said. And
building a timing model from a position no longer mutates PINT's module-level
`StandardTimingModel`, which used to leak the coordinates into every later call in the
process and into any other PINT user.

The clock correction is now applied *before* the barycentric one, and the barycentric
correction and the spacecraft position lookup are evaluated at the clock-corrected time,
which is what HEASOFT `barycorr` does. On NuSTAR, where the clock correction reaches
25 ms, the old order was +1146 ns mean and 1878 ns peak away from `barycorr`; it is now
+22 ns mean and 60 ns peak, the same as with no clock file at all. Two crashes are gone
with it: a clock file that does not quite cover the events no longer raises a length
mismatch, and a network failure while looking for the latest clock file now falls back to
a cached one instead of raising `UnboundLocalError`. Clock files are cached under the
user's cache directory rather than re-downloaded into the working directory on every run.

The `(0.5 - TIMEPIXR) * TIMEDEL` half-bin shift is no longer applied. `barycorr` does not
apply one, and on RXTE PCA data, where `TIMEDEL` is a single 954 ns clock tick and
`TIMEPIXR` is 0, it moved every event 477 ns -- five times the accuracy target -- while
leaving `TIMEPIXR` itself unchanged in the output header, so the file went on claiming a
convention its times no longer followed.

Columns are now looked up without regard to case, as the FITS standard says they should
be. Missions use that freedom: Chandra writes its event times in a column called `time`
and its orbit times in `Time`. Because the `GTI` extension beside them *does* use
capitals, a case-sensitive lookup produced no error but something worse -- a file whose
good-time intervals had been barycentred and whose events had not -- and on the orbit
side it found no velocity columns and quietly differentiated the position instead.
`RA_TARG`/`DEC_TARG` is also read now, which is where Chandra puts the target position;
it writes no `RA_OBJ` at all, and its `RA_NOM` can be arcminutes away.

`fits_open_remote` no longer turns a plain permission error into an `UnboundLocalError`.
Its retry with anonymous access only applies to a URL, and on a local path the `except`
branch had nothing to try and fell through to returning a name that was never assigned.

Downloading an input file no longer corrupts astropy's download cache. It was fetched
with `cache=True` and then moved out of the cache directory, so the cache index went on
claiming a URL whose contents had walked away -- which astropy's own
`check_download_cache` reports as damage, and which breaks every later download in that
environment, this package's or anyone else's.
