Times the orbit file does not cover are no longer silently extrapolated. An
interpolating spline answers every time it is asked about, so a spacecraft position
guessed past the end of an orbit file, or coasted through a gap in one, used to reach the
output looking exactly like a measured one. `OrbitCoverage` now says where a file really
knows the spacecraft position — allowing one sampling interval past each sample, since
that is what interpolating between two samples already assumes — and a time that misses by
more than 10 s is acted on: inside a good time interval it is an error, outside every good
time interval the row is dropped with a warning, and a file with no GTIs has all of its
times treated as good.

`TSTART` and `TSTOP` are handled separately, because they routinely hold the range that
was *requested* rather than the one that was delivered. A Fermi LAT extraction sets
`TSTART` to the start of the requested window while the GTIs and the spacecraft file begin
whenever the data does — 1455.6 s later on one M82 observation, which is why `gtbary`
refuses that file outright. Such a keyword is now moved to the edge of the good time
intervals and corrected there, with a loud warning, instead of being answered from an
extrapolation worth up to 2.3 ms.
