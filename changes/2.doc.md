New documentation describing how the correction is computed, how accurate it is
measured to be against HEASOFT `barycorr`, and what is currently known to be wrong.

`tools/benchmarks/` holds the measurements behind the performance work, with a README
recording the machine, the numbers and what each script asks. Every speed or memory claim
in `docs/technical_details.md` and `docs/known_issues.md` is reproducible from there.

Measured whether leaning on `numba` more would pay: the vector arithmetic a fused kernel
could replace is 0.6 % of the per-event cost and 104 MB of a 905 MB peak, against 60 %
and 865 MB for astropy's JPL ephemeris evaluation, which numba cannot reach. Recorded as
a decision not to write it, with the phase-by-phase timings and `tracemalloc` peaks in
`tools/benchmarks/`. This also corrects the memory attribution first written alongside
the interpolation grid, which credited the saving to this package's own `(N, 3)`
temporaries rather than to astropy's ephemeris call.
